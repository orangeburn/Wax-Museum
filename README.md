# 蜡像馆

![蜡像馆背景图](background.png)

《蜡像馆》是一套面向中文互动悬疑体验的叙事游戏引擎原型：玩家用自然语言直接行动，系统把角色属性、掷骰检定、场景物件、NPC 回合与故事线索编织成一局可持续推进的悬疑现场。当前项目已经支持模板化危机场景、LLM 辅助生成故事骨架、基于行动点与先攻排序的回合流程、本地存档，以及让玩家与 NPC 在同一信息边界下推进局势的规则内核。

## 当前能力（现状）

- 模板局可直接开玩：默认模板可即开即玩，适合作为基础体验入口。
- 自定义故事可用：输入一句 Prompt，即可生成故事背景、角色、地点与主线节点。
- 角色随题材动态生成：不再固定为预设职业模板，角色设定会跟随故事题材变化。
- 角色秘密目标可追踪：每个可选角色都会获得私密任务，并在游玩中持续记录进度。
- 自然语言行动可直输：玩家可直接输入行动描述，不依赖固定选项操作。
- 故事滤镜已接入主流程：不合理动作会结合地点、背包、主线与角色状态，被重解释为当前故事内成立的行为。
- 偏航动作可被吸收：偏离主线的行动不会伪造“假支线”，而是转化为贴近现场的即时叙述。
- NPC 可参与回合制推进：NPC 拥有先攻顺序、行动点、位置、公开状态与私有状态，会在自己的回合中行动。
- NPC 支持 LLM 驱动决策：服务端会为 NPC 构建受限的可见信息 `ActorObservation`，LLM 只基于这些信息产出行动意图；未配置模型或调用失败时，会自动回落到规则决策。
- 玩家与 NPC 信息边界已隔离：玩家快照不会暴露 NPC 的隐藏动机和私有记忆，NPC 决策也不会直接读取完整服务器真相。
- 场景已向物件级细化：地点内可包含家具、容器、设备、人物与危险源，线索和关键物资会挂在具体物件上。
- 回合节奏已进一步规则化：每次有效互动消耗 1 点行动点，先攻顺序按每回合掷骰排序，角色会按顺序轮流推进。
- 本地存档完整可用：支持保存、恢复与继续旧局。

## 项目结构

- `client/`：Vite + React 前端
- `server/`：Express 服务端、规则引擎、AI 服务接入
- `shared/`：共享类型、模板和常量

## 基本架构

项目按“共享规则类型 + 服务端权威状态 + 前端操作界面”的方式组织：

- `shared/` 定义游戏会话、角色、地点、物件、故事节点、NPC 观察视图、行动解析结果等类型，同时保存默认模板和通用常量。
- `server/` 负责创建和推进游戏会话。`session-engine` 是规则核心，统一处理行动点、先攻、掷骰检定、倒计时、地点移动、物件交互、秘密目标、NPC 回合和存档快照。
- `server/src/services/ai.ts` 是 LLM 适配层，负责把玩家自然语言解析为规则行动、生成自定义故事大纲和剧本草案、生成动态角色，并在可用时为 NPC 产出行动意图。
- `client/` 负责玩家体验，包括首页、创建故事、草案确认、游戏会话页、本地存档入口和响应式界面。前端不直接裁决游戏真相，只向服务端提交意图并渲染服务端返回的公开快照。

整体流程是：玩家输入自然语言行动，AI 服务先尝试把它归一成有限行动类型；规则引擎再根据当前位置、背包、场景物件、故事节点和角色状态裁决结果；随后服务端刷新公开快照、事件日志和下一步可行动作提示。

## NPC 自主行动

NPC 已经进入回合制主循环，不再只是静态背景角色。每个 NPC 会带有公开身份、态度、位置、线索、公开状态，以及只保存在服务端的私有状态，例如核心目标、短期目标、压力、记忆和上次行动。

每一轮开始时，系统会为玩家和所有 NPC 掷先攻并分配行动点。玩家行动结束后，如果下一个行动者是 NPC，服务端会持续推进 NPC 队列直到轮到玩家。NPC 的行动可能包括观察、移动、分享线索、施压或尝试处理现场问题，并会影响危险值、伤害、公开叙述和自己的私有记忆。

LLM 可用时，服务端会先为 NPC 构造受限的 `ActorObservation`：只包含该 NPC 合理可见的地点、角色、公开状态、可行动作、近期日志和自身目标摘要。模型只能基于这份观察输出自然语言意图和行动类型，不能读取完整服务器真相、其他角色秘密或不可见地点。模型不可用、超时、返回非法内容或未配置 `LLM_API_KEY`/`LLM_MODEL` 时，系统会自动回落到规则决策，保证模板局和本地测试仍可稳定运行。

## 环境准备

安装依赖：

```bash
npm install
```

如果要使用自定义故事生成，请在项目根目录准备 `.env`，至少配置：

```bash
LLM_API_KEY=your_key
LLM_MODEL=your_model
LLM_BASE_URL=https://api.moonshot.cn/v1
```

未配置模型时，默认模板玩法仍可运行，但自定义故事生成会直接报错。

公网测试时不建议把自己的 LLM 密钥写入服务端环境变量。前端右上角提供常驻的 API Key 入口，访客可以填入自己的 `API Key`、`模型` 和 `Base URL`。这些信息只保存在访客浏览器的 `localStorage` 中，请求时通过 `X-LLM-API-Key`、`X-LLM-Model`、`X-LLM-Base-URL` 临时传给后端，服务端不会写入存档。

自定义故事当前可通过一次生成获得可开玩的初始内容（剧本与角色），并在后续游玩中结合规则引擎持续推进体验。

## Cloudflare Pages

项目已包含 `wrangler.jsonc`，构建产物目录为 `client/dist`。如果前端和 API 不同源部署，请在 Cloudflare Pages 环境变量中配置：

```bash
VITE_API_BASE_URL=https://your-api.example.com
```

然后执行：

```bash
npm run build
npx wrangler pages deploy client/dist
```

注意：当前后端是 Express 服务，不能只靠 Pages 静态托管运行完整 API。可以把后端部署到支持 Node/Express 的服务，或后续迁移到 Cloudflare Workers/Containers，再用 `VITE_API_BASE_URL` 指向它。

## 当前实现边界（现状）

- 当前定位仍是单人原型，尚未扩展为完整的多人群像系统。
- 自定义故事已支持动态地点、动态角色、秘密目标、NPC 回合与故事滤镜，但底层仍由部分规则引擎提供稳定性兜底。
- NPC 已具备“按可见信息行动”的架构基础，但还不是完整的通用多智能体沙盒；目前 LLM 决策会被归一到有限动作类型，再由规则引擎裁决结果。
- 复杂场景和物件交互已经进入规则层，但仍处于“新物件结构逐步替换旧硬编码目标”的过渡阶段。
- 故事滤镜当前以“动作重解释”为核心能力，尚未演进为完全自由生成的长期剧情代理。
