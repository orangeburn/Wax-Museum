# 蜡像馆

![蜡像馆背景图](background.png)

《蜡像馆》是一个玩家与 AI agent 共同驱动的互动悬疑叙事游戏。它包含具备受限观察、私有状态、回合制行动与 LLM/规则混合决策能力的 NPC agent。玩家用自然语言直接行动，系统把角色属性、掷骰检定、场景物件、NPC 回合与故事线索编织成一局可持续推进的悬疑现场。
当前项目已经支持模板化危机场景、LLM 辅助生成故事骨架、基于行动点与先攻排序的回合流程、本地存档，以及让玩家与 NPC agent 在同一信息边界下推进局势的规则内核。

## 当前能力（现状）

- 模板局可直接开玩：默认模板可即开即玩，适合作为基础体验入口。
- 自定义故事可用：输入一句 Prompt，即可生成故事背景、角色、地点与主线节点。
- 角色随题材动态生成：不再固定为预设职业模板，角色设定会跟随故事题材变化。
- 角色秘密目标可追踪：每个可选角色都会获得私密任务，并在游玩中持续记录进度。
- 自然语言行动可直输：玩家可直接输入行动描述，不依赖固定选项操作。
- 故事滤镜已接入主流程：不合理动作会结合地点、背包、主线与角色状态，被重解释为当前故事内成立的行为。
- 偏航动作可被吸收：偏离主线的行动不会伪造“假支线”，而是转化为贴近现场的即时叙述。
- NPC 可参与回合制推进：NPC 拥有先攻顺序、行动点、位置、公开状态与私有状态，会在自己的回合中行动。
- NPC 支持 LLM 驱动决策：服务端会为 NPC 构建受限的可见信息 `ActorObservation`，LLM 只基于这些信息产出行动意图；未配置模型或调用失败时，会自动回落到规则决策。
- 玩家与 NPC 信息边界已隔离：玩家快照不会暴露 NPC 的隐藏动机和私有记忆，NPC 决策也不会直接读取完整服务器真相。
- 公屏对话已接入会话：玩家可以向所有角色发送公开信息，NPC 的 LLM 决策也可以产生公屏发言；公屏消息会保存为 `PublicMessage`，并随存档恢复。
- 同场景环境动态可见：系统会把开局事件、玩家行动、NPC 行动和关键场景变化记录为 `SceneEnvironmentEntry`，只展示当前位置可见的近期动态。
- 场景已向物件级细化：地点内可包含家具、容器、设备、人物与危险源，线索和关键物资会挂在具体物件上。
- 回合节奏已进一步规则化：每次有效互动消耗 1 点行动点，先攻顺序按每回合掷骰排序，角色会按顺序轮流推进。
- 结算故事可生成：当会话进入逃脱或失败阶段后，可以进入结算页，基于事件日志、公屏发言和角色状态生成角色高光、时间线与一篇中短篇故事。
- 同场景环境动态：同一场景下，各个角色的行动可见。
- 本地存档完整可用：支持保存、恢复与继续旧局。

## 项目结构

- `client/`：Vite + React 前端，线上演示时直接在浏览器内运行游戏流程、存档和用户自带 LLM 调用
- `server/`：Express 服务端与规则/AI 适配层的原型实现，保留给本地 API 测试和后续服务端化参考
- `shared/`：共享类型、模板和常量

## 基本架构

项目按“共享规则类型 + 服务端权威状态 + 前端操作界面”的方式组织：

- `shared/` 定义游戏会话、角色、地点、物件、故事节点、NPC 观察视图、行动解析结果、公屏消息、现场环境记录和结算报告等类型，同时保存默认模板和通用常量。
- `server/src/engine/session-engine.ts` 是规则核心，统一处理行动点、先攻、掷骰检定、倒计时、地点移动、物件交互、秘密目标、NPC 回合、公屏消息、环境记录和存档快照；线上演示版会由前端直接复用这套规则。
- `client/src/lib/api.ts` 在演示版中不再请求 `/api/*`，而是把会话保存在浏览器 `localStorage`，并在用户填写 API Key 时由浏览器直连兼容 OpenAI 的 `/chat/completions`。
- `client/` 负责完整玩家体验，包括首页、创建故事、草案确认、游戏会话页、公屏、现场动态、结算故事页、本地存档入口和响应式界面。

整体流程是：玩家输入自然语言行动，浏览器内的适配层把它归一成有限行动类型；规则引擎再根据当前位置、背包、场景物件、故事节点和角色状态裁决结果；随后前端刷新公开快照、事件日志、公屏消息、现场动态和下一步可行动作提示。

公屏发言走独立的轻量通道：玩家发送的文字会被长度和空白归一化后加入 `publicMessages`，不会消耗行动点；NPC 在自己的回合中也可以向公屏发言，最近消息会进入 NPC 的受限观察视图，成为后续决策的一部分。

## NPC 自主行动

NPC 已经进入回合制主循环，不再只是静态背景角色。每个 NPC 会带有公开身份、态度、位置、线索、公开状态，以及只保存在服务端的私有状态，例如核心目标、短期目标、压力、记忆和上次行动。

每一轮开始时，系统会为玩家和所有 NPC 掷先攻并分配行动点。玩家行动结束后，如果下一个行动者是 NPC，服务端会持续推进 NPC 队列直到轮到玩家。NPC 的行动可能包括观察、移动、分享线索、施压或尝试处理现场问题，并会影响危险值、伤害、公开叙述和自己的私有记忆。

LLM 可用时，原型服务端可以为 NPC 构造受限的 `ActorObservation`；纯前端演示版为了避免保存测试者密钥，默认使用本地规则决策推进 NPC。模型不可用、跨域失败、超时或未填写 API Key 时，系统会自动回落到本地剧本与规则兜底，保证公网演示仍可稳定运行。

NPC 行动会同步写入公开叙事和同场景环境动态。玩家只能看到当前位置的近期环境记录，因此不同地点的行动痕迹不会被直接全局广播；公屏则相反，定位为所有角色都能看见的公开频道。

## 结算故事

当本局进入 `escaped` 或 `failed` 阶段后，游戏页会出现“生成结算故事”入口。结算页会汇总本局事件日志、公屏对话、角色状态和主线结果，生成：

- 角色高光：玩家与 NPC 各自的结局、关键行为和收束句。
- 本局时间线：按重要节点整理的事件摘要。
- 中短篇故事：把整局游玩记录改写成一篇可阅读的中文悬疑短篇。

如果右上角已配置可用的 LLM，结算内容会优先由模型生成；如果没有可用模型，前端会使用本地规则从已有记录中生成稳定兜底版本。重新生成会覆盖当前存档里的 `finale` 报告。

## 环境准备

安装依赖：

```bash
npm install
```

如果要运行 Express 原型服务并使用服务端 LLM，可在项目根目录准备 `.env`：

```bash
LLM_API_KEY=your_key
LLM_MODEL=your_model
LLM_BASE_URL=https://api.moonshot.cn/v1
```

公网演示不需要配置 `.env`。测试者可以在页面右上角填写自己的 `API Key`、`模型` 和 `Base URL`；未填写或浏览器直连模型失败时，会使用本地兜底剧本。

右上角 API Key 入口只把信息保存在当前浏览器的 `localStorage`，不会上传到项目作者的服务器或 Cloudflare 环境变量。注意：浏览器直连第三方 LLM 服务时，部分服务可能因为 CORS 策略拒绝请求；这时仍会自动使用本地兜底内容。

自定义故事当前可通过一次生成获得可开玩的初始内容（剧本与角色），并在后续游玩中结合规则引擎持续推进体验。

## Cloudflare Pages

项目已改为纯前端演示部署：Cloudflare Pages 只需要构建并发布 `client/dist`，不需要后端、Worker、KV、D1，也不需要配置 `CLOUDFLARE_API_TOKEN` 或 LLM 密钥。

Cloudflare Pages GitHub 部署配置：

- 框架预设：`None`
- 构建命令：`npm run build`
- 构建输出目录：`client/dist`
- 根目录：`/`

如需用 Wrangler 手动上传：

```bash
npm run build
npx wrangler pages deploy client/dist
```

线上存档保存在测试者自己的浏览器 `localStorage`，换设备、换浏览器或清缓存后不会同步。

## 当前实现边界（现状）

- 当前定位仍是单人原型，尚未扩展为完整的多人群像系统。
- 自定义故事已支持动态地点、动态角色、秘密目标、NPC 回合与故事滤镜，但底层仍由部分规则引擎提供稳定性兜底。
- NPC 已具备“按可见信息行动”和“读取近期公屏”的架构基础，但还不是完整的通用多智能体沙盒；目前 LLM 决策会被归一到有限动作类型，再由规则引擎裁决结果。
- 复杂场景和物件交互已经进入规则层，但仍处于“新物件结构逐步替换旧硬编码目标”的过渡阶段。
- 同场景环境动态目前是近期可见变化摘要，不是完整的物理世界模拟或长期环境状态树。
- 故事滤镜当前以“动作重解释”为核心能力，尚未演进为完全自由生成的长期剧情代理。
- 结算故事会尽量利用本局日志和公屏内容，但仍是一次性报告生成，不会反向改变已完成的会话裁决。
